## Unreleased

- Feature: add the `deepseek-v41-flash-dsgb10-spark-tp4` procedure for Picom-code's `pico-dgx-ds4` at `f2117916` (source path `ds41f-4xgx10-switchless`). It runs DeepSeek V4.1 Flash 1017 on four Sparks on a switched RoCE fabric with the authored `engine/server/service.sh start|stop|status`, builds the engine with CMake and the front-end with cargo, and serves on head port 8888 with `/health` readiness. Source-owned recipes can now declare an optional `upstream.status` argv, and with it an empty `containers` list. For such workloads the coordinator's state comes from that command (exit 0 = running), which runs in the background with a 60 s timeout and a 3-minute restart grace before a terminal failure. Start refuses with `upstream.foreign_service` while status already reports a service, and stop must leave status reporting not running. Non-coordinator ranks without containers are placement holders: they hold leases, report `running` once armed and run or observe nothing. Agents advertise `upstream-status-v1`, and plans require it. A reviewed source edit removes upstream's API-key file requirement, so port 8888 is unauthenticated. The lifecycle verifier now follows `. "$(dirname "$SELF")/name"` sources when `SELF` is the script's own path. The head agent needs cargo on `PATH` and an unlimited memlock limit (see README).

- Feature: a node `serve-port` label (integer 1-65535, validated on `PUT /nodes/{id}`) sets the host port for every single-node deployment on that node. It is exposed to recipes as the `${node.port}` template and frozen into the deployment placement, so the plan digest, endpoint, endpoint recovery, readiness/verify probes of the serving port, native port publishing, upstream environment, conflict checks, `port:<node>:<port>` leases, restarts and recipe-update reconstruction all use the same port. Multi-node deployments, unlabelled nodes, existing deployments and source-owned procedures that do not bind `${node.port}` keep their recipe port. The single-Spark Qwen3.8 Flash Next vLLM (2.4.0) and TensorFold (3.1.0), Qwen3.8 27B TensorFold (1.1.0) and Qwen3.8 27B SGLang (2.3.0) recipes bind `PORT` to it, and the compiled SGLang `PORT` rewrite now always uses `${node.port}`. Their declared ports remain the fallback.
